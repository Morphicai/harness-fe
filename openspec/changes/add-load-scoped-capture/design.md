# Design: Load-Scoped Capture

## Identity Layering

```
session (dev-server process)
└── tab (browser tab, sessionStorage-persistent across refresh)
    └── load (one page load, refresh creates a new one)
        └── events (network / storage / console / rrweb / …)
```

| Id | Generated by | Lifetime | Storage |
|---|---|---|---|
| `sessionId` | `mcp-server` when build plugin connects | dev-server uptime (+ 60s grace) | `store.openSession` |
| `tabId` | `runtime-client`, persisted to `sessionStorage` | Tab lifetime (survives refresh) | `__hfe_tab_id__` key |
| `loadId` | `runtime-client` constructor, `crypto.randomUUID()` | One page load only | In-memory only |

`loadId` MUST NOT be written to `sessionStorage` — that is the property that makes it refresh-scoped. WebSocket reconnects within the same load reuse the same `loadId`; only a real page navigation/refresh produces a new one.

## Protocol Surface

`HelloFrame.loadId` is required for `role === 'runtime-client'` and absent for build plugins. The bridge rejects runtime-client hellos missing `loadId` with an explicit `hello.ack` error so the failure mode is visible during development.

`EventFrame` and `CommandFrame` do not carry `loadId`; the connection registered at `hello` time carries the load context implicitly. The bridge stamps `loadId` onto every persisted `StoreEvent` it derives from a runtime-client event.

A new event name `EVENT_NAME.PAGE_LOAD = 'page.load'` carries the initial snapshot payload (page metadata, viewport, storage). A new event name `EVENT_NAME.STORAGE = 'storage'` carries storage mutation events.

## Initial Snapshot

The runtime client emits `PAGE_LOAD` immediately after receiving `hello.ack` and before any other capture event. The payload contains:

- `page`: `url`, `title`, `referrer`, `userAgent`
- `viewport`: `w`, `h`, `dpr`
- `storage.local` / `storage.session`: full `Storage` contents as `Record<string,string>`; each value truncated at 32 KB and the whole object truncated at 256 KB with a `truncated` flag
- `storage.cookie`: `document.cookie` raw string (HttpOnly cookies remain invisible — this is expected)
- `performance` (optional): selected `PerformanceNavigationTiming` fields, when available

The bridge persists the full payload as a `t: 'load'` timeline event and a derived `LoadMeta` row to the per-tab `loads.jsonl` sidecar.

## Network Capture: Non-Pollution Contract

Every capture patch follows five rules:

1. **Preserve identity.** The replacement function is named (so `.name === 'fetch'`), its `.length` and `.toString()` mirror the original via `defineProperty`. `instanceof` checks remain unbroken because no `Response` / `Request` / `XMLHttpRequest` instance is wrapped.
2. **Isolate errors.** Capture failures are swallowed inside `safeEmit`; they never become business exceptions or unhandled rejections.
3. **Do not change values or timing.** The original `fetch` Promise is returned directly. `response.clone()` is called synchronously after `await originalFetch`, and the clone is read on a side branch.
4. **Prefer passive observation.** `XMLHttpRequest` events use `addEventListener('loadend', …)` rather than overwriting `onload`. Cookie changes prefer `CookieStore.addEventListener('change', …)` over redefining `document.cookie`.
5. **Inject first.** The vite/webpack plugin already injects capture as the first `<head>` script; this contract MUST hold after any future plugin refactor, otherwise business modules can capture stale references to `fetch` before patching.

The fetch patch emits two store events per call, both keyed by an internally generated `id`:

- `t: 'req'` with `method`, `url`, `reqHeaders`, `reqBody`, optional `reqBodyTruncated`
- `t: 'res'` with the same `id`, `status`, `respHeaders`, `respBody`, `durationMs`, optional `respBodyTruncated`

Pairing on the consumer side is by `id`; SSE responses still emit `req` immediately so long streams are visible before they end.

### Body capture rules

- Read response body via `response.clone()` so the business path is unaffected.
- 256 KB cap per body, applied after `text()` resolves. Excess is truncated with `truncated: true`.
- `Content-Type` routing:
  - JSON-like: `text()`, attempt `JSON.parse` for ergonomic viewing.
  - Text-like (`text/*`, XML, urlencoded): `text()`.
  - SSE (`text/event-stream`): pump the cloned `ReadableStream`; cancel and emit when the cap is hit so neither memory nor stream lifetime is unbounded.
  - Binary (default): record `[binary <byteLength>B]` placeholder only.
- Headers are recorded by default; values for `Authorization`, `Cookie`, `x-api-key`, `x-auth-*` (case-insensitive) are replaced with `[redacted <originalLength>]`.

### Self-traffic guard

Any internal request the runtime might issue carries an `init.__hfeInternal = true` flag; the patch short-circuits to the original fetch for those requests. A URL deny list also matches HMR / dev-server internals (`/sockjs-node`, `.hot-update.`) to avoid feedback loops.

### Repeated install

`installFetchPatch` marks the patched function with `__hfePatched = true`; re-running is a no-op. Each install returns a dispose function that restores the original reference, used by tests.

## XHR

The current implementation replaces `window.XMLHttpRequest` with a wrapper constructor, breaking `instanceof XMLHttpRequest` in business code. The new implementation patches the prototype:

- `XMLHttpRequest.prototype.open` records `method`, `url`, and resets the per-instance metadata bag on the actual XHR instance (using a non-enumerable symbol key).
- `XMLHttpRequest.prototype.setRequestHeader` records header pairs into the metadata bag.
- `XMLHttpRequest.prototype.send` records request body, attaches a `loadend` listener that reads `status`, `responseText` (with the same cap and content-type rules as fetch), and emits the matching `req` and `res` events.

No constructor is replaced; `instanceof`, prototype chain, and `XMLHttpRequest.LOADING`-style constants all stay native.

## Storage Capture

| Source | Mechanism |
|---|---|
| Same-tab `setItem` / `removeItem` / `clear` | Patch the three methods on `Storage.prototype`; `this === localStorage` chooses `which`. |
| Cross-tab writes | `window.addEventListener('storage', …)` (native; only fires in *other* tabs). |
| Cookie changes (modern browsers) | `cookieStore.addEventListener('change', …)`. |
| Cookie changes (fallback) | 1 s polling `document.cookie` and emit diff entries; only when `cookieStore` is unavailable. |

The `document.cookie` getter/setter is NOT redefined — that property is a well-known fingerprinting target and overriding it breaks some libraries.

Each event payload: `{ op: 'set' | 'remove' | 'clear', which: 'local' | 'session' | 'cookie', key?: string, value?: string }`. Empty `value` for redacted keys, configurable via a key denylist later.

## PerformanceObserver (Resource Timing)

A `PerformanceObserver({ type: 'resource', buffered: true })` is registered after install to emit one event per resource entry: `{ url, initiatorType, transferSize, encodedBodySize, startTime, responseEnd }`. This is purely additive — no monkey-patching, and the entries appear regardless of whether fetch/XHR was used.

## Store Layout and APIs

The store keeps a single timeline per tab and adds a sidecar index per tab:

```
project/sessions/{sessionId}/tabs/{tabId}/
├── meta.json
├── timeline.jsonl       (single source of truth; events carry load)
├── recording.jsonl
└── loads.jsonl          (append-only LoadMeta index)
```

Rationale for not introducing `loads/{loadId}/` subdirectories:

- Frequent debug refreshes would create dozens of small files per tab.
- Per-load directories force timeline reads to merge across files for cross-load queries.
- rrweb recording is already chunked by time and slicing by load reduces to a `[startedAt, endedAt]` window query.

`StoreEvent.load` is required at the type level; `JsonlStore.append` validates the field is present and throws otherwise. New event types `'load'` and `'storage'` join the existing extensible string enum.

New `IStore` methods:

- `listLoads(sessionId, tabId): LoadMeta[]`
- `getLoad(sessionId, tabId, loadId): LoadMeta | undefined`
- `sliceRecordingsByLoad(sessionId, tabId, loadId): RecordingChunk[]` (resolves `loadId` to a time window and delegates to `sliceRecordings`)

`TailOptions` and `SearchOptions` gain `loadId?: string` — when present, results are filtered server-side rather than client-side.

When the runtime emits `PAGE_LOAD`, the bridge:

1. Calls `store.append(sessionId, { t: 'load', load: loadId, tab: tabId, d: payload })`.
2. Appends a `LoadMeta` row to `loads.jsonl` (`startedAt: ts`, `endedAt: undefined`).
3. If the same `tabId` has a prior `LoadMeta` with no `endedAt`, rewrites that row in place to set `endedAt = ts` (i.e. previous load ended when the new one began).

When a tab closes, the bridge closes the last open `LoadMeta.endedAt` to `disconnectedAt`.

## Dashboard

The session detail view becomes load-scoped by default. The selector lists loads newest-first with a short summary (URL + storage counts). Selecting a load:

- Calls `store.tail({ loadId })` for the timeline column.
- Calls `store.sliceRecordingsByLoad(sessionId, tabId, loadId)` for the recording column.
- Renders the load's `LoadMeta.initial` summary at the top of the column.

An "All loads" option restores the unfiltered view; in this mode each timeline row carries a load badge so cross-load reading remains possible.

## Security and Resource Bounds

- Body capture is bounded at 256 KB per request. SSE streams stop accumulating beyond the cap and `cancel()` the cloned reader.
- Header redaction is non-configurable in the initial slice; a follow-up may expose a per-project denylist.
- Storage snapshots cap at 32 KB per value and 256 KB per snapshot.
- The `__hfeInternal` flag and URL denylist prevent capture loops on the runtime's own traffic.

## Out of Scope (Explicit)

- WebSocket / `EventSource` body capture.
- Service Worker or browser-extension based capture (does not work for first-paint requests or restricted by deployment shape).
- `console` object lockdown via `defineProperty` (breaks developer ergonomics).
- Body sanitizers beyond the small SENSITIVE header regex.
- Compatibility with stores written before this change.
