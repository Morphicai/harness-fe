# Proposal: Add Load-Scoped Capture

## Why

Harnessa-FE today has two identity layers — a dev-server-level `sessionId` and a browser-tab-level `tabId` (stored in `sessionStorage`, surviving refresh). Neither corresponds to "one page load." When the same tab refreshes during a debug session, all events flow into a single timeline with no way to slice by refresh. This hurts AI debugging in three ways:

1. The agent cannot reason about "what state did the page boot into this time," because no initial snapshot of `localStorage` / `sessionStorage` / `cookie` / viewport is captured.
2. The agent cannot ask "what happened in this refresh vs. the previous one," because events from multiple page loads are interleaved.
3. The agent cannot read AI-conversation responses, because `fetch` capture only records URL/method/status/duration — request and response bodies (including SSE streams) are dropped even though the schema reserves the fields.

These gaps matter most for the AI-conversation debugging workflow that motivates Harnessa-FE: a refresh that "should fix it" produces a new request/response/storage trace, and the agent has no structured way to inspect that trace.

Because Harnessa-FE has not been released, we can introduce the load concept without compatibility shims.

## What Changes

This change introduces **load** as a first-class observability scope alongside session and tab, and fills the runtime-capture gaps that the AI-conversation workflow depends on:

- A new `loadId` identifies a single page load, generated by the runtime client at construction time (not persisted to `sessionStorage`).
- A new `PAGE_LOAD` event captures initial state per load: page metadata, viewport, and full `localStorage` / `sessionStorage` / `cookie` snapshot under documented size caps.
- The fetch capture path is rewritten so it records request and response bodies (including SSE streams) and request/response headers, with redaction for sensitive headers, without changing business-visible fetch behavior.
- The XHR capture path is rewritten to patch `XMLHttpRequest.prototype` instead of replacing the constructor, restoring `instanceof XMLHttpRequest` semantics for downstream code.
- Storage mutations (`Storage.prototype` set/remove/clear, cross-tab `storage` events, Cookie changes) are captured as a dedicated event stream.
- Browser resource loads not visible to fetch/XHR (img, css, font, worker, prefetch) are captured passively via `PerformanceObserver`.
- The store layer treats `load` as a required field on `StoreEvent`, persists a per-tab `loads.jsonl` index, and supports `loadId` filters in `tail` / `search` / recording slicing.
- The dashboard defaults to a per-load view, showing the initial snapshot at the top and offering an "All loads" aggregate.

## Goals

- Give an AI agent a stable answer to "what changed across this refresh" by separating events per load.
- Make the AI-conversation request and response (including streaming SSE) inspectable end-to-end.
- Capture initial browser state at every load so the agent can compare bootstrap state across loads.
- Keep capture monkey-patching transparent to business code: identity-preserving, error-isolated, time-and-value-faithful, and removable.
- Keep the storage layout a single source of truth per tab (no per-load subdirectories) so timeline queries stay cheap.

## Non-Goals

- WebSocket / EventSource body capture (deferred until a real consumer appears).
- A general-purpose body sanitizer beyond a small sensitive-header redaction list.
- Replacing `safeClone` semantics for non-network capture paths.
- Production analytics or end-user telemetry.
- Backwards compatibility with stores created before this change (project is pre-release).

## Initial Delivery Shape

The first slice should land a minimal closed loop: a runtime client that generates a `loadId`, sends `PAGE_LOAD` with initial storage, captures fetch bodies, and pushes everything through the store with `load` required. The dashboard load selector and storage-mutation capture follow next. WebSocket capture and richer redaction stay out of scope.
